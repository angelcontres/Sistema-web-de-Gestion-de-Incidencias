# 7. Criterios de Inicio / Cierre y Herramientas

## 7.1 Criterios de Inicio

Los criterios de inicio establecen las condiciones mínimas que deben cumplirse antes de ejecutar los casos de prueba diseñados en el presente documento. Su objetivo es garantizar que el entorno de pruebas sea estable y que los resultados obtenidos sean confiables y reproducibles.

Para iniciar la ejecución de las pruebas deberán cumplirse las siguientes condiciones:

- El entorno de desarrollo deberá encontrarse desplegado y operativo mediante contenedores Docker.
- La base de datos deberá estar correctamente inicializada con los datos de prueba definidos en el apartado anterior.
- La API REST desarrollada en Laravel deberá responder correctamente a las solicitudes del cliente.
- La interfaz web deberá estar disponible y comunicarse correctamente con los servicios backend.
- Los casos de prueba deberán haber sido revisados y aprobados por el equipo de desarrollo.
- Los usuarios de prueba y sus respectivos roles deberán encontrarse previamente configurados.

---

## 7.2 Criterios de Cierre

La fase de ejecución de pruebas se considerará finalizada cuando se cumplan las siguientes condiciones:

- Se hayan ejecutado la totalidad de los casos de prueba definidos en la matriz de diseño.
- Todos los resultados obtenidos se encuentren documentados en el registro de pruebas correspondiente.
- Las incidencias detectadas durante la ejecución hayan sido registradas y clasificadas según su severidad.
- Se hayan recopilado las evidencias necesarias (capturas de pantalla, respuestas JSON, registros de auditoría y demás evidencias técnicas).
- La matriz de trazabilidad haya sido actualizada, verificando la cobertura del **100%** de los requisitos funcionales y no funcionales.

---

## 7.3 Herramientas de Apoyo

Durante la ejecución de las pruebas se emplearán herramientas que permitan validar el comportamiento funcional del sistema, verificar el correcto funcionamiento de la API REST y documentar las evidencias obtenidas.

| Herramienta                   | Propósito                                                                              |
| ----------------------------- | -------------------------------------------------------------------------------------- |
| Docker                        | Despliegue y ejecución del entorno de pruebas.                                         |
| Laravel                       | Framework backend sobre el cual se validará la lógica de negocio y los servicios REST. |

# 8. Gestión de Riesgos de Ejecución

Durante la ejecución de los casos de prueba pueden presentarse eventos que afecten la continuidad, confiabilidad o validez del proceso de verificación del sistema. Por ello, se identifican los principales riesgos asociados a la fase de pruebas del Sistema Web de Gestión de Incidencias Georreferenciadas, evaluando su probabilidad de ocurrencia, el impacto que tendrían sobre el proyecto y las estrategias definidas para reducir sus efectos.

La identificación temprana de estos riesgos permite planificar acciones preventivas y correctivas, contribuyendo a una ejecución más controlada de las pruebas y a una mayor confiabilidad de los resultados obtenidos.

## 8.1 Matriz de Riesgos

| ID       | Riesgo                                                                                                                        | Nivel                                            | Acción de mitigación                                                                                                      |
| -------- | ----------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------- |
| **R-01** | El entorno Docker no inicia correctamente debido a errores de configuración o dependencias.                                   | **Alto** (Probabilidad: Media / Impacto: Alto)   | Verificar previamente la configuración de los contenedores y mantener una copia funcional del entorno de despliegue.      |
| **R-02** | La base de datos contiene información inconsistente o incompleta para ejecutar los casos de prueba.                           | **Alto** (Probabilidad: Media / Impacto: Alto)   | Preparar un conjunto de datos de prueba controlado y restaurar la base de datos antes de cada ciclo de pruebas.           |
| **R-03** | Cambios recientes en el código generan comportamientos distintos a los considerados durante el diseño de los casos de prueba. | **Medio** (Probabilidad: Media / Impacto: Medio) | Revisar los cambios implementados antes de la ejecución y actualizar los casos de prueba cuando sea necesario.            |
| **R-04** | Fallas de comunicación entre el frontend y la API REST impiden validar determinadas funcionalidades.                          | **Medio** (Probabilidad: Baja / Impacto: Alto)   | Verificar previamente la disponibilidad de la API mediante Postman y revisar la configuración de red entre los servicios. |
| **R-05** | Los usuarios de prueba no poseen los permisos requeridos para ejecutar determinados escenarios.                               | **Bajo** (Probabilidad: Baja / Impacto: Medio)   | Validar previamente la configuración de roles y permisos definidos para cada usuario de prueba.                           |
| **R-06** | Pérdida de evidencias (capturas de pantalla, respuestas JSON o registros) durante la ejecución de las pruebas.                | **Bajo** (Probabilidad: Baja / Impacto: Medio)   | Centralizar el almacenamiento de las evidencias y realizar respaldos periódicos durante la fase de pruebas.               |

---

## 8.2 Estrategia General de Mitigación

Con el propósito de reducir el impacto de los riesgos identificados, el equipo adoptará las siguientes medidas durante la fase de ejecución de pruebas:

- Verificar el correcto funcionamiento del entorno Docker antes de iniciar cada sesión de pruebas.
- Mantener una copia de respaldo de la base de datos con los datos de prueba definidos en el presente documento.
- Ejecutar pruebas preliminares sobre la API REST utilizando Postman para confirmar la disponibilidad de los servicios.
- Documentar de forma continua las evidencias obtenidas durante la ejecución de los casos de prueba.
- Registrar cualquier incidencia detectada para facilitar su análisis y posterior corrección.
- Realizar revisiones cruzadas entre los integrantes del equipo para validar los resultados obtenidos y asegurar la consistencia de las evidencias.
